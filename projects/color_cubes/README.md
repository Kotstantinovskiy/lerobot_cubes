# Четыре кубика: данные для VLA

Задача: по текстовой команде взять кубик нужного цвета и положить его в фиксированный лоток. Демонстрации записываются ведущей рукой. Голос и дообучение — следующие этапы.

Перенос этих рук на другой компьютер: [TRANSFER.md](TRANSFER.md). Калибровки включены в [calibration/](calibration/README.md); проектные скрипты находят их относительно файла конфигурации, без привязки к домашнему каталогу исходного Mac.

`record.py` запускает штатный `lerobot.scripts.lerobot_record` из этой установки. LeRobot сохраняет изображения, состояния, действия и текст задания в своём формате датасета. Один запуск записывает один цвет; последующие запуски добавляют другие цвета в тот же датасет через `--resume`. Загрузка в Hugging Face отключена.

Сохранено 6 локальных эпизодов: 3 красных, 2 синих, 1 жёлтый. На этом подключении последние синий и жёлтый эпизоды записаны без таймаутов. Это не доказывает устранение редких сбоев. ### Воспроизведение записанного эпизода

Это автоматическое движение ведомой руки по сохранённым командам, без визуальной коррекции. Кубик и рабочая зона должны соответствовать началу демонстрации. Проверяется калибровка, стартовая поза достигается плавно, при большом отклонении от команды скрипт останавливается. При завершении или ошибке отключается момент моторов.

Последний жёлтый эпизод имеет индекс 5; синий — 4. Проверка команды без подключения и запуск на половинной скорости:

```bash
.venv/bin/python projects/color_cubes/replay.py --episode 5 --speed 0.5 --dry-run
.venv/bin/python projects/color_cubes/replay.py --episode 5 --speed 0.5
```

На половинной скорости добавляются промежуточные команды при прежней частоте управления. Синий и жёлтый эпизоды прошли воспроизведение примерно за 62,5 секунды, плюс 8 секунд плавного подхода к старту. На полной скорости первый синий повтор остановился из-за превышения защитного порога.

### Что хранится в Git

Точную причину предыдущих сбоев это не доказывает: одновременно изменились разрешение и способ настройки камеры. Более ранние выводы ниже относятся к историческим настройкам.

## Проверка выбора камер — 17 сентября 2026

В последнем эпизоде на 730 кадров `top` действительно показывал стол, а `wrist` — комнату с веб-камеры. Этот эпизод сохранён отдельно в `camera_check/rejected-webcam-episode` с отметкой `DO_NOT_TRAIN.json`. Он не входит в новый датасет. Самая первая запись Full HD на 553 кадра содержит настоящий вид камеры захвата и осталась на месте, но имеет ранее описанную проблему временной шкалы.

Теперь `macos_device_name` задаёт точное имя устройства. Локальный драйвер LeRobot разрешает имя в индекс непосредственно при подключении и повторно проверяет список устройств после открытия. Отсутствующее или неоднозначное имя вызывает ошибку, числовой индекс не используется как запасной вариант. Используется сортировка устройств по `uniqueID`, как в [OpenCV 4.12 AVFoundation](https://github.com/opencv/opencv/blob/4.12.0/modules/videoio/src/cap_avfoundation_mac.mm#L338-L361); индексы списка ffmpeg нельзя напрямую считать индексами OpenCV.

Для этой функции установлен пакет `pyobjc-framework-AVFoundation`. При новой установке добавь его:

```bash
uv pip install --python .venv/bin/python pyobjc-framework-AVFoundation
```

Свежие изображения из двух одновременно подключённых камер визуально проверены: `camera_check/named-devices/top.jpg` и `wrist.jpg`. Настоящая Innomaker не выдала кадры в 720p при текущем подключении; в 1080p кадры получены. Перед новым сбором используется отдельный `data/color_cubes_named`, запуск без `--resume`.

Повторный 30-секундный замер с привязкой по именам и этими разрешениями: 731 кадр за 30,005 с (24,36 fps), сохранены 1462 PNG, ожиданий дольше 200 мс не было. Это проверка чтения и сохранения без команд движения.

Проверить имена и поведение при пропавшей камере без оборудования:

```bash
.venv/bin/python projects/color_cubes/test_camera_names.py
```

Проверить захват и сохранение с текущими размерами каждой камеры без движения рук:

```bash
.venv/bin/python projects/color_cubes/benchmark_capture.py --fps 25 --seconds 30 --read-timeout-ms 500
```

## Настройка

LeRobot и драйвер Feetech установлены в текущую `.venv`. Для повторной установки в новое окружение, при наличии `uv`, из `/Users/boba/lerobot`:

```bash
uv pip install --python .venv/bin/python -e .
```

Для рук SO-100 / SO-101 нужен также драйвер Feetech:

```bash
uv pip install --python .venv/bin/python -e '.[feetech]'
```

Проверка установки без подключения устройств:

```bash
.venv/bin/python -m lerobot.scripts.lerobot_record --help
```

Открой `config.json` и замени значения `SET_...`:

- `robot`: ведомая рука, которая берёт кубики; `teleop`: ведущая рука, которой управляешь ты.
- `type`: пользователь подтвердил SO-101; в конфигурации уже указаны `so101_follower` и `so101_leader`.
- `port`: актуальный порт каждой руки. В корне репозитория есть ранее сохранённый `leader_port.txt`, но подключение могло измениться.
- `id`: существующие идентификаторы калибровок твоих рук. Если калибровки нет, LeRobot предложит её при подключении.
- `robot.cameras.top.index_or_path` и `wrist.index_or_path`: проверены и заполнены как 0 и 1 соответственно. Ненужную камеру можно удалить целиком.

Порты рук заполнены по текущему подключению и сохранённому `leader_port.txt`. Используются найденные калибровки `my_so100_follower` и `my_so100_leader`: это имена существующих файлов, тип оборудования задан отдельно как SO-101.

По `LOCAL_CAMERAS.md` верхняя камера — Sport Cam, камера захвата — Innomaker-U20CAM-1080p-S1. После переподключения индексы могут меняться. Имена AVFoundation нельзя просто подставлять вместо индексов OpenCV. Текущие режимы: верхняя Sport Cam — 1280×720, камера захвата Innomaker — 1920×1080. Камеры запрашивают 30 fps, цикл записи — 25 fps, окно просмотра выключено. Прогрев — до 8 секунд. В режиме 640×480 камера захвата не выдала кадр за время ожидания. Проверочные снимки и отчёты находятся в `camera_check/`. Сохранённая перспективная обрезка стола в запись пока не применяется.

Команды запускаются из `/Users/boba/lerobot`:

```bash
.venv/bin/python -m lerobot.scripts.lerobot_find_cameras opencv
```

Красный, синий, зелёный и жёлтый — начальный набор. Замени `tasks`, если у тебя другие цвета. Английский текст задания выбран как начальная разметка; на инференсе используй такие же формулировки. После начала записи сохраняй названия камер, FPS и параметры суставов неизменными.

## Запуск

### Проверка управления без записи

После установки LeRobot и заполнения `robot.type/port/id` и `teleop.type/port/id` запусти из `/Users/boba/lerobot`:

```bash
.venv/bin/python projects/color_cubes/teleoperate.py
```

Двигай ведущую руку — ведомая повторяет движения. Остановка: **Ctrl+C**. По умолчанию камеры отключены, поэтому их индексы для этой проверки заполнять не нужно. Датасет не создаётся. Если у рук нет сохранённой калибровки, LeRobot сначала предложит её выполнить.

Ограничить проверку 30 секундами управления:

```bash
.venv/bin/python projects/color_cubes/teleoperate.py --seconds 30
```

После настройки камер можно включить изображение через `--cameras`. Посмотреть команду без подключения оборудования:

```bash
.venv/bin/python projects/color_cubes/teleoperate.py --dry-run
```

### Запись демонстраций

Посмотреть команду без подключения к рукам и камерам (работает даже до заполнения настроек):

```bash
.venv/bin/python projects/color_cubes/record.py --color red --dry-run
```

Первая запись:

```bash
.venv/bin/python projects/color_cubes/record.py --color red --episodes 5
```

Добавить другие цвета в тот же датасет:

```bash
.venv/bin/python projects/color_cubes/record.py --color blue --episodes 5 --resume
.venv/bin/python projects/color_cubes/record.py --color green --episodes 5 --resume
.venv/bin/python projects/color_cubes/record.py --color yellow --episodes 5 --resume
```

`--episodes` — число новых эпизодов в этом запуске. Новые данные хранятся в `data/color_cubes_named` внутри проекта независимо от текущей рабочей папки. Первый пробный эпизод Full HD сохранён отдельно в `data/color_cubes`; добавлять к нему кадры другого размера или FPS нельзя. Первый запуск с новыми настройками делай без `--resume`. Скрипт не удаляет существующие данные. Начни с короткой пробной сессии и просмотри записи перед массовым сбором.

## Во время записи

До запуска подготовь кубики и исходную позу: запись начинается после подключения устройств. Один эпизод: исходная поза → захват указанного кубика → перенос → отпускание в лотке. Сеанс использует один цвет, указанный в `--color`; он не распознаётся автоматически.

- Стрелка вправо завершает текущий этап раньше (запись или паузу для сброса).
- Стрелка влево запрашивает перезапись текущего эпизода.
- Escape завершает сеанс; текущий эпизод при штатном выходе может сохраниться, поэтому это не команда отбросить неудачную попытку.

По умолчанию запись длится до 30 секунд, затем отводится 20 секунд на возврат сцены. Во время сброса телеуправление продолжает работать. Для клавиш нужен доступ запускающего приложения к мониторингу ввода / универсальному доступу macOS. В первом запуске система сообщила, что разрешения нет: пока это не исправлено, запись завершается по таймеру, на горячие клавиши полагаться нельзя.

Меняй позиции кубиков и записывай примерно поровну каждый цвет. Для одинаковой раскладки записывай разные команды с восстановлением сцены. Можно чередовать цвета короткими сеансами по одному эпизоду. Не сохраняй неудачные попытки как успешные демонстрации. Для проверки будущей модели оставь отдельные новые раскладки.

Это скрипт сбора данных, а не обученная политика. Физическая запись требует заполненной конфигурации и подключённого оборудования.

Замеры без просмотра (`benchmark_capture.py`) читают состояния обеих рук и камеры, сохраняют временные PNG тем же писателем LeRobot. Сохранились все 1462 изображения двух камер. Полные 25 fps не достигнуты, расхождение по времени около 2,6%; новый реальный эпизод ещё нужно проверить.

## Пауза камеры и таймаут

Повторная демонстрация 720p прервалась примерно через 20 секунд: камера захвата не выдала новый кадр за стандартные 200 мс. Эпизод не сохранился. В последующем 90-секундном замере сбой не повторился (максимальное ожидание захвата 47,3 мс), поэтому причина единичной задержки — USB, устройство или системное планирование — не установлена.

В локальный OpenCV-драйвер LeRobot добавлен параметр `read_timeout_ms`. Для этого проекта он выставлен в 500 мс; значение по умолчанию для других проектов осталось 200 мс. Ожидание нового кадра дольше 200 мс выводит предупреждение. Кадр из прошлого не подставляется; если новый не появляется за 500 мс, запись всё ещё останавливается. Это обработка краткой паузы, а не подтверждённое устранение аппаратной причины. Паузы также влияют на фактический FPS.

`verify_recording.py` запускает полный 60-секундный цикл записи LeRobot с чтением рук, но без отправки команд моторам и без переключения момента. Диагностические данные сохраняются только в `camera_check/recording-check-...`, не в обучающий датасет. `diagnostic-report.json` содержит фактическую длительность и FPS. Повторять проверку можно, когда обычная запись и телеуправление остановлены:

```bash
.venv/bin/python projects/color_cubes/verify_recording.py
.venv/bin/python projects/color_cubes/test_camera_timeout.py
```

Пустая папка прерванной демонстрации перенесена в `camera_check/aborted-recording-20260917-202216`. Следующая настоящая демонстрация красного запускается без `--resume`.

Проверка полного цикла с таймаутом 500 мс завершилась успешно: 1462 кадра за 60,040 с (24,35 fps), обе видеодорожки декодированы полностью. Команды движения не отправлялись. Это подтверждает работу сохранения на неподвижной установке; возможный сбой кабеля при движении этим тестом не исключён.
