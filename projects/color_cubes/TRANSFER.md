# Перенос на другой компьютер

Инструкция рассчитана прежде всего на **те же физические SO-101**. Код, данные 6 эпизодов и обе калибровки находятся в репозитории. Проверено на исходном Mac с Python 3.12.9; установка на другом компьютере пока не проверялась.

## 1. Получить репозиторий и видео

Установи Git и Git LFS средствами своей ОС. Затем:

```bash
git lfs install
git clone --recurse-submodules git@github.com:Kotstantinovskiy/lerobot_cubes.git
cd lerobot_cubes
git lfs pull --include='projects/color_cubes/data/color_cubes_vga/videos/**'
```

SSH-ключ должен иметь доступ к репозиторию. Вместо SSH можно использовать HTTPS-адрес репозитория со своей авторизацией. Без Git LFS в видеофайлах могут остаться текстовые указатели.

## 2. Установить окружение

Для macOS/Linux с установленным Python 3.12, из корня репозитория:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[feetech]' pandas pyarrow
```

Зависимости берутся из локального `pyproject.toml`; это не точный lock-файл исходного окружения. Для воспроизведения запись камер не используется. Для камер на macOS дополнительно:

```bash
.venv/bin/python -m pip install 'opencv-python-headless==4.12.0.88' pyobjc-framework-AVFoundation
```

Для записи видео/диагностики нужен FFmpeg; установи его средствами ОС. Сравнительный диагностический скрипт пока использует путь `/opt/homebrew/bin/ffmpeg` и требует адаптации на другой платформе. Разреши приложению, из которого запускаешь Python, доступ к камерам на macOS. На Linux нужны права на последовательные порты и видеоустройства.

На Windows команды Python находятся в `.venv\Scripts\python.exe`; эта установка и аппаратная работа здесь не проверялись.

## 3. Указать порты именно этих рук

```bash
cp projects/color_cubes/config.json projects/color_cubes/config.local.json
.venv/bin/python -m serial.tools.list_ports -v
```

В `config.local.json` замени `robot.port` на порт ведомой руки. Для записи/телеуправления также замени `teleop.port` на порт ведущей. На macOS это обычно `/dev/tty.usbmodem…`, на Linux — `/dev/ttyACM…`, на Windows — `COM…`. Проверь соответствие рук, а не только наличие порта.

Сохрани ID и `calibration_dir`: пути автоматически вычисляются относительно файла конфигурации, а не домашнего каталога старого Mac. Файл `config.local.json` исключён из Git.

Для повтора нужны только ведомая рука, её питание и USB. Ведущая рука и камеры не подключаются. Для новых демонстраций нужны обе руки и камеры. Настройки камер в исходном конфиге рассчитаны на macOS: на Linux/Windows нужно убрать `macos_device_name`, установить `macos_explicit_mode=false` и выбрать подходящие `index_or_path` и поддерживаемые режимы. Удалять эти настройки ради одного replay не требуется.

## 4. Проверить без движения

```bash
.venv/bin/python projects/color_cubes/replay.py --config projects/color_cubes/config.local.json --episode 5 --speed 0.5 --dry-run
```

Команда читает действия и файл калибровки, но не открывает порт и не проверяет реальные моторы. Эпизоды: красный — 0, 1, 2; синий — 3, 4; жёлтый — 5.

## 5. Воспроизвести

Повтор идёт по сохранённым командам без коррекции по изображению. Сохрани положение основания руки и рабочей поверхности, поставь кубик в исходное положение и освободи рабочую зону. Затем для жёлтого эпизода:

```bash
.venv/bin/python projects/color_cubes/replay.py --config projects/color_cubes/config.local.json --episode 5 --speed 0.5
```

Перед движением скрипт проверяет соответствие калибровки моторным настройкам. При несовпадении он останавливается: не подменяй значения ради обхода проверки. Подход к старту — 8 секунд, траектория на исходном Mac занимала около 62,5 секунды. Остановка — Ctrl+C; при выходе отключается момент моторов.

Сами записи и настройки FPS сохранены как собраны: номинально 20 fps, реальная частота была немного ниже. Перенос файлов не исправляет это ограничение данных и не гарантирует точного совпадения времени и результата на другом компьютере.
